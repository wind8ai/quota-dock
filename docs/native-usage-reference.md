# 原生用量指示器参考（2026-10-26）

## 依据与范围

只读检查本机安装的 ChatGPT/Codex 应用，版本 `26.1021.31345`。资源来源为 `/Applications/ChatGPT.app/Contents/Resources/app.asar` 内的 `webview/assets/rail-menu-288bd90d0a6e.js` 和 `rail-menu-2edcecdaec7c.css`。这里记录观察结论，不复制应用实现代码，不修改安装包，也不把内部组件当作稳定公开 API。

## 已确认的实现方式

- React 界面内的 SVG 指示器，显示尺寸 28 × 28，viewBox 为 32 × 32。
- 读取传入的 `usage.rate_limit`，按窗口时长识别约 5 小时与 7 天的限额；两段圆弧分别表示相应剩余额度。只有周额度可用时使用单环。
- 通过归一化路径长度与 stroke-dashoffset 改变填充长度，描边宽 1.75、圆头端点。
- 低于 15% 的弧段使用警示色；悬停显示五小时或每周剩余百分比，提示延迟 350 ms，提示位于右侧并间隔 8。
- 悬停弧段放大至 1.08 倍，另一段降低透明度；支持减少动态效果。常规进度变化约 0.4 秒。
- 同一控件还有 reserve 和 credits 展示分支，不能把所有形态都视为同一种额度。

随后只读追踪同版本 `app-initial-feb30b196d11.js`：原生常规读取 `/wham/usage`，默认轮询基准为 30 秒，可随用量缩短但至少 5 秒；支持前台聚焦刷新。部分身份与功能开关允许推送，通过用量订阅与 WebSocket 更新，检查用户、账号和生成时间，并保留轮询恢复路径。这是当前安装包的实现观察，不是公开接口承诺；没有调用或复用这些私有接口。

## QuotaDock 的采用与差异

- 采用清晰轮廓、低额度警示、减少动态效果和独立间隔的思路。
- 不复制环形外观：QuotaDock 用液位和常显大数字，充足时用青蓝色，避免与原生中性线环混淆。
- 3.0.9 槽体为 36 × 104 pt，再上移 18 pt；与截图中的原生圆环预留约 20 pt，仍是固定几何定位，不是实时读取原生控件边界。
- 3.1.0–3.1.1 使用过官方 app-server 的 `account/rateLimits/read`。随后账号路由发现和直接额度请求均失败，3.1.2 按用户要求恢复本地 JSONL，不再启动 CLI。单根优先显示 5 小时，否则每周，不声称等价于原生实时推送；本地回执最长有效 15 分钟。
- `scripts/state-preview.swift` 直接绘制生产视图；侧栏、中心图标与头像使用用户于 2026-10-26 授权的截图（`docs/images/sidebar-reference.png`）。圆环采用 1.75 pt 圆头描边，按每列同一模拟额度重绘：满环、部分进度、低额度警示、空轨道和无数据虚线。它是单周期效果示意，不表示原生所有状态的完整复刻；头像不变。
