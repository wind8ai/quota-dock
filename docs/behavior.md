# 定位与额度规则

**中文** | [English](behavior.en.md)

## 窗口定位

液体槽为 36 × 104 pt，中心距目标窗口左侧 26 pt，底边距头像顶部 70 pt。对应面板左侧偏移 8 pt、底部偏移 107 pt，比 3.0.8 再上移 18 pt；按当前布局与原生用量圆环留出约 20 pt 的视觉间隔。数字使用最多 15 pt 的白色等宽重体与扩散黑色阴影（模糊半径 4 pt），数字直接叠在液面上，不使用底板，长数值按宽度缩小。至少 50% 为青蓝色，20% 到不足 50% 为琥珀色，低于 20% 为红色；无数据使用中性灰轮廓。

目标是窗口所有者为 `ChatGPT` 或 `Codex`、普通窗口层级、宽至少 800 pt、高至少 600 pt 的可见窗口。mini／宠物浮动窗口不参与选择；找不到主窗口时隐藏。定位值针对当前新版账号栏布局，应用界面变化后可能需要调整 `Sources/QuotaCore/BadgeLayout.swift`。

首次发现优先选择面积最大的候选窗口，之后保持该窗口身份，不因前台或 Space 切换重新绑定。目标暂时不可见时隐藏，关闭后才重新发现。首次选择仍是几何启发式，不能保证识别所有特殊对话框。

主窗口可见时，每秒核对一次用量条在系统窗口列表中的实际可见状态。前两次检查失败时重新隐藏并显示面板；第三次仍失败则关闭旧面板并创建新面板，复用原视图以保留额度和动画。重建后十秒内不再执行恢复动作，避免频繁创建；正常显示或主窗口隐藏会清除连续失败计数。正常显示时不反复置顶，主窗口不可见时不尝试恢复。

运行 `build/QuotaDock.app/Contents/MacOS/QuotaDock --diagnose` 可进行只读诊断：退出码 0 表示面板在最大可见候选主窗口的预期位置；1 表示面板缺失或位置不符；2 表示没有可见主窗口（可能只是位于其他 Space）；3 表示无法查询。诊断不启动第二个用量条，不输出窗口标题、聊天或账号内容。多个主窗口并存时，诊断参考最大候选窗口，可能与已绑定的窗口不同，须结合输出中的窗口 ID 判断。

此前已实际验证窗口所有者为 ChatGPT 的主窗口，以及同时开启 mini 时的显示。3.0.5 的文件选择框、跨屏和全屏切换尚未完成人工验收；回归测试覆盖文件选择框排在更大主窗口前方的选择行为。

## 数据来源与有效期

通过本机已登录 ChatGPT 的 Codex CLI，以 stdio 调用官方 `account/rateLimits/read`。启动时读取，主窗口可见时每 5 秒、隐藏时每 30 秒读取；切回窗口时立即检查是否该刷新，不绕过最小间隔。失败后按 5、10、20、40、60 秒逐步退避，成功后恢复正常间隔，同一时间最多一个请求。每次使用独立短生命周期子进程，15 秒通信超时，退出时先关闭 stdin、再按需终止自己的进程，不启动 HTTP 服务或模型任务。

优先读取 `rateLimitsByLimitId.codex`；没有多桶字段时才接受明确标记为 codex 的 legacy 结果。按 `windowDurationMins` 选择 300 分钟（5 小时），否则 10080 分钟（每周）。不把 primary 固定解释为某一周期，不误用 Spark、credits 或 reserve。其他窗口长度目前显示未知。

剩余值为 `100 - usedPercent`，保留服务端小数、显示四舍五入整数。服务端更新可上升或下降，不再强制同周期递减。读取失败显示 `--`；内存快照最多有效 60 秒，到达 resetsAt 后立即失效，不自行推断重置成 100%。唤醒后清除旧显示并重新读取。

3.1.0 删除了 JSONL 扫描、旧 QuotaStabilizer 和跨重启缓存代码。旧 `quota-history-v2` 偏好数据即使仍在磁盘上也不会读取，不作为备用数据源。

## 登录与诊断

优先查找 PATH 中的 codex、常用 CLI 安装路径，再查找已安装 Codex/ChatGPT 应用中的 CLI。找不到、未登录、API-key-only 身份、协议不兼容或无支持的额度窗口时显示未知。请先在终端确认 Codex CLI 已用 ChatGPT 登录；工具不自动登录、切换账号或读取令牌文件。

读取前后通过 account/read 比较进程返回的邮箱与计划类型，只在一致时发布结果。这些字段只用于内存校验，不写入日志或缓存。当前接口不返回完整桌面选中账号／workspace 身份，因此该检查不能证明桌面多账号选中身份与 CLI 完全相同。

```sh
build/QuotaDock.app/Contents/MacOS/QuotaDock --diagnose-quota
```

退出码 0 表示成功，输出来源、周期、剩余值、观测和重置时间；退出码 1 输出明确失败类别，不输出邮箱、令牌或 credits 余额。

## 已知边界

调度每秒检查一次，5 秒是最小查询开始间隔；本机实际观察相邻查询约 5–6 秒，且还需叠加接口响应时间。系统繁忙、网络变慢或失败退避时等待会更长，不能保证固定延迟上限。

官方服务端快照比日志更直接，但仍是可见时约 5 秒轮询，还需叠加接口响应耗时，不等同于原生组件的推送时效。原生与本工具必须比较同一账号、同一周期、接近的观测时间。当前只显示一根主额度，不展示双周期、credits 或 reserve。屏幕定位仍是固定账号栏几何关系，不读取头像像素；原有多屏和长期运行验证边界不变。
