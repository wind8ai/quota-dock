# 定位与额度规则

**中文** | [English](behavior.en.md)

## 窗口定位

液体槽为 36 × 104 pt，中心距目标窗口左侧 26 pt，底边距头像顶部 102 pt。对应面板左侧偏移 8 pt、底部偏移 139 pt，比 3.1.3 再上移 32 pt，为原生用量圆环、更新按钮及“有可用更新”提示留出空间。数字使用最多 15 pt 的白色等宽重体与扩散黑色阴影（模糊半径 4 pt），数字直接叠在液面上，不使用底板，长数值按宽度缩小。至少 50% 为青蓝色，20% 到不足 50% 为琥珀色，低于 20% 为红色；无数据使用中性灰轮廓。

目标是窗口所有者为 `ChatGPT` 或 `Codex`、普通窗口层级、宽至少 800 pt、高至少 600 pt 的可见窗口。mini／宠物浮动窗口不参与选择；找不到主窗口时隐藏。定位值针对当前新版账号栏布局，应用界面变化后可能需要调整 `Sources/QuotaCore/BadgeLayout.swift`。

首次发现优先选择面积最大的候选窗口，之后保持该窗口身份，不因前台或 Space 切换重新绑定。目标暂时不可见时隐藏，关闭后才重新发现。首次选择仍是几何启发式，不能保证识别所有特殊对话框。

主窗口可见时，每秒核对一次用量条在系统窗口列表中的实际可见状态。前两次检查失败时重新隐藏并显示面板；第三次仍失败则关闭旧面板并创建新面板，复用原视图以保留额度和动画。重建后十秒内不再执行恢复动作，避免频繁创建；正常显示或主窗口隐藏会清除连续失败计数。正常显示时不反复置顶，主窗口不可见时不尝试恢复。

运行 `build/QuotaDock.app/Contents/MacOS/QuotaDock --diagnose` 可进行只读诊断：退出码 0 表示面板在最大可见候选主窗口的预期位置；1 表示面板缺失或位置不符；2 表示没有可见主窗口（可能只是位于其他 Space）；3 表示无法查询。诊断不启动第二个用量条，不输出窗口标题、聊天或账号内容。多个主窗口并存时，诊断参考最大候选窗口，可能与已绑定的窗口不同，须结合输出中的窗口 ID 判断。

此前已实际验证窗口所有者为 ChatGPT 的主窗口，以及同时开启 mini 时的显示。2026-10-20 用户确认 3.0.8 的全屏切换与文件选择小窗显示正常；回归测试覆盖文件选择框排在更大主窗口前方的选择行为。真实跨屏、屏幕插拔及长期睡眠唤醒仍未完成全面人工验收。

## 数据来源与有效期

3.1.2 恢复本地日志读取，删除了 CLI 子进程及 JSON-RPC 查询路径。默认读取 `~/.codex/sessions`；设置 CODEX_HOME 时读取该目录下的 sessions。不修改代理、登录状态或 Codex 应用。

每次检查最近修改的 12 个 JSONL 文件，每个最多读取尾部 2 MB。仅解析 event_msg / token_count 中 limit_id=codex 的 rate_limits，兼容 payload.rate_limits 和 payload.info.rate_limits。优先选 window_minutes=300，否则选 10080，不把 primary 固定解释为每周，也不使用 Spark。

按回执的 ISO 8601 时间选择最新记录，支持带毫秒和不带毫秒的时间戳，不用文件修改时间冒充观测时间。尾部截断或尚未写完的 JSON 行会被跳过。最新记录已过期时，不退回到更早的其他重置周期。

剩余值为 100 - used_percent，保留小数并四舍五入显示，正数最低显示 `1`。本地回执的已用比例达到 100% 不足以确认套餐耗尽：剩余零值仅在 `rate_limit_reached_type=rate_limit_reached` 时显示 `0`，其他情况显示 `≤1`。字段缺失或为 null 不表示仍允许使用，也不从额度余额大于零推断套餐仍有剩余；workspace 花费上限等其他原因不当作套餐耗尽。旧缓存缺少耗尽标记时同样保持不确定。

允许更新后的值回升，不恢复只降不升规则。15 分钟后仅标记为旧数据，保留数字并在槽顶显示小钟，暂停气泡。读数不得跨过 resets_at；没有记录或已重置时显示未知，不自行推断恢复为 100%。

主窗口可见时最小读取间隔 5 秒，隐藏时 30 秒，每秒检查调度。读取不重叠；本地缺少数据时不再按网络失败退避，以便新日志出现后及时恢复。唤醒后清除旧显示并重新读取。

最近一次回执保存到应用偏好，按日志目录隔离，跨重启恢复。旧记录不会覆盖较新记录，读取失败不会清空同周期缓存。缓存保留原始观测时间，不因重复读取而延长新鲜期。过期或非法数值不会显示；旧 quota-history-v2 不导入。诊断可读取缓存，但不会修改它。

## 扣余额提醒

读取 `credits.balance` 的非负十进制余额，只比较 `unlimited=false` 的有限额度。同一周期中，时间更新的回执余额低于前一条已知余额时，标记已经发生扣费；不以套餐百分比、`allowed` 或是否持有额外额度推断扣费。时间较旧或相同的回执、首次余额、相同余额和充值不会新触发提醒。回执缺少余额时保留同周期内最后已知余额。

周期按窗口时长和重置时间匹配，容忍响应头造成的最多两秒偏差。每次读取在既有的 12 个文件、每个尾部 2 MB 范围内，按回执时间复原余额变化；缓存补充两次读取间的余额差。提醒与余额一起持久保存，直到周期重置或当前周期结束，不因空闲、充值或重启消失。

提醒时管子变红，中间出现透明断口和发亮的裂纹，标注“已扣费”，液体停止动画。仍显示套餐数字，避免把额外额度余额误当套餐百分比。它是已发生扣费的提醒，不代表应用已阻止继续使用。

本地回执有延迟，无法预警第一笔扣费；只扫描有限历史时，未留下两条可比较余额且缓存也没有基线，就需要等待后续余额变化。日志不含可靠账号标识，多账号恰好具有相同周期时仍可能混淆；不能归因到某条聊天。提醒不参与付款或账号设置。

## 诊断

```sh
build/QuotaDock.app/Contents/MacOS/QuotaDock --diagnose-quota
```

退出码 0 输出 local-session-log、周期、最后读数、显示文本、耗尽确认、扣费提醒、最后已知余额、回执时间及年龄，并以 recent-local-observation 或 cached-local-observation 区分状态；退出码 1 表示当前周期没有可用记录。诊断不输出会话正文、文件名、邮箱或令牌。

## 已知边界

日志只有在 Codex 写入额度回执后才更新。空闲、其他设备使用额度或没有本地回执时，不能保证与原生实时圈同步。小钟表示最后记录已经超过 15 分钟，不代表服务端当前值。

原生在 `allowed=true` 时会把显示下限设为 1，即使已用比例达到 100%；这个条件也不能证明还剩套餐额度。本地日志没有该字段，额外额度可能已经扣费而耗尽原因仍为 null。`≤1` 只表示套餐剩余比例处于末段且缺少确认，不保证可以继续使用套餐，也不表示额外额度的余额或扣费速度。

本地日志可能混有不同账号的记录，目前无法据此确认桌面当前账号。只读取最近 12 个文件的尾部也可能漏掉其他文件中的回执。缓存按日志目录隔离，不能解决同一目录内多个账号混用的问题。

主动查询在没有聊天任务时也可进行，本轮复测官方接口曾成功，但之前的间歇性 CLI 故障不因此视为已解决。用户选择继续无 CLI 模式，本版不自动查询服务端。既有窗口定位、多屏和睡眠验证边界不变。
